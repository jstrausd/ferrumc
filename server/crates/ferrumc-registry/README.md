# ferrumc-registry

Pinned Minecraft 1.21.8 registry data for the server, exposed as deterministic,
hardcoded runtime constants.

The runtime is dependency-free and does no I/O or JSON parsing at startup: every
value is either a `const` baked at compile time (block/dimension) or a
`static` array generated at build time from a vendored snapshot (items, blocks
and entity types/worldgen/biomes). The vendored upstream snapshots (`fixtures/protocol/1_21_8/` and this crate's
`data/`, plus `docs/fixtures/minecraft-1.21.8-original/`) are
parsed only by `build.rs` and by `#[cfg(test)]` drift guards that re-parse the
real data and assert the generated tables still match,
so a re-pin to a newer data version cannot silently desync them.

## What it provides

- Version constants: `MINECRAFT_VERSION`, `PROTOCOL_VERSION`, `DATA_VERSION`.
- `block_state` — fixed block-*state* (palette) ids for the flat-world block set.
- `connection` — built-in fence-family and connection-exception facts pinned to
  Minecraft 1.21.8 / Paper Build 60. Unknown block names are refused; these facts
  do not evaluate support shapes or runtime datapack overrides.
- `default_block_state_id(name)` — resource-location → default state id lookup.
- `dimension` — overworld geometry constants (`OVERWORLD`, `MIN_Y`, `HEIGHT`).
- `biome` — all 65 original biome resources and two original multinoise presets
  through opaque checked local identities, with full preserved JSON definitions
  and stats. The 7593 Overworld/five Nether quantized parameter entries retain
  original order and repetitions as static borrowed slices; lookups and iteration
  allocate nothing. `PLAINS` remains compatible with the existing flat world.
- `item` — item lookups: `lookup_item_protocol_id`, `lookup_item_name`,
  `item_max_stack`, `item_to_block_state` (generated from `data/items.json` +
  `data/item_to_block_mapping.json`).
- `entity_type` — all 151 original 1.21.8 entity-type names and wire ids through
  opaque validated `EntityTypeId`; allocation-free name/id lookup, player
  classification and ordered borrowed iteration. Entity types are distinct from
  instance UUIDs, wire entity ids and local storage handles. This table supplies
  identity data; metadata, spawning, physics, tracking and AI need consumers.
- `worldgen` — all 60 original noise, 35 density-function and seven noise-settings
  resources through three distinct opaque IDs. Exact canonical/bare lookup and
  static iteration allocate nothing. Noise supplies exact f64 parameters;
  `OriginalDefinition` supplies the exact export JSON slice, measured limits and
  typed dependencies. Compilation, seed binding, samplers, biomes, surfaces and
  active terrain generation require separate World consumers.

## Data provenance

Block-state ids are fixed protocol constants and must match the vanilla 1.21.8
client jar. They are derived from PrismarineJS/minecraft-data; see
`fixtures/protocol/1_21_8/manifest.toml` for the exact pinned commit and
checksums, and `fixtures/protocol/1_21_8/NOTICE` for attribution.

Biome and dimension-type ids are *not* fixed constants — they are server-assigned
indices into the dynamic registries sent during the configuration phase — so this
crate exposes stable resource-location strings and checked opaque biome resource
identities. Private local slots are neither wire IDs nor original bootstrap
ordinals. Later configuration and chunk consumers must explicitly agree on their
registry order and palette ID mapping.

Entity types use the existing, unchanged [CAT-02.1 original fixture](../../../docs/fixtures/minecraft-1.21.8-original/entity-types.json).
The build generator rejects malformed schema, duplicate names/ids, gaps,
foreign namespaces, wrong registry/default, missing player and inputs above
64 KiB. Runtime construction refuses unknown inputs with `None`, including
out-of-range ids; it does not use the original defaulted-registry pig fallback.
Player classification is generated by exact name from that same data.
The complete [original oracle](tests/fixtures/entity_types_1_21_8.manifest.json)
retains version, input/output hashes and Mojang/Microsoft data attribution.
The [export helper](tests/reference/export_entity_types.py) requires the pinned
full original registry report before writing and checks all 151 original
names/ids against the CAT-02.1 subset. Offline checks need no Java or network:

```sh
python3 crates/ferrumc-registry/tests/reference/export_entity_types.py --self-test --check
```

Run from the `server/` workspace. Regeneration uses `--export --report` with
the verified `reports/registries.json` from CAT-02.1; existing original fixtures
remain unchanged. Data equality does not establish live Paper/gameplay parity.

Worldgen uses the unchanged [original export](../../../docs/fixtures/minecraft-1.21.8-original/worldgen.json)
and its independently pinned manifest/version metadata. Build admission checks
duplicate decoded keys, per-family resource counts, finite codec parameters,
reference domains, block/property validity, density cycles and unknown forms.
The largest definition is 129853 bytes; all definitions fit the explicit
128 KiB/4096-node/depth32/256-container/256-byte-string caps. Root depth is zero,
and nodes count both object keys and values. Dependencies are charged before
insertion and capped at 2048 occurrences/512 distinct values per definition.
The complete source fixture has separate 4 MiB/131072-node/container1024 bounds.
These are builtin producer limits, not arbitrary datapack support.

Noise amplitudes are generated with `f64::from_bits`, retaining all original
positions, including zeros. Their pinned scope is 1..16 amplitudes in 0..2,
firstOctave -16..-1. `NoiseResourceId::parameters()` has no seed, RNG or sampler.
Density/Noise holder names resolve fully at build time; external block/biome/
codec types and positional RNG names remain explicitly typed. The original
Clamp Directcodec and Shift `NoiseHolder` paths are distinct from unary
`DensityHolder` paths. World must check its own cumulative compiler/graph/work
limits and fail unsupported external dependencies before use.

All 102 runtime definitions are tested against exact slices of the hashchecked
export. The [offline original verifier](tests/reference/verify_builtin_worldgen.py)
also checks every selected generated resource against the verified official
bundle/inner JAR, exact decimal contents and all 195 noise-amplitude f64 bits:

```sh
python3 crates/ferrumc-registry/tests/reference/verify_builtin_worldgen.py
```

Run from `server/`; its default source directory is the existing CAT-02.1 local
cache `.codex-tmp/original-1.21.8`, or pass `--original-dir`. It reads local inputs
only. Datagen/JAR raw bytes agree; export/JAR whitespace and decimal token
spelling can differ while exact values agree. Data/resource parity is separate
from density evaluation, natural worldgen and seed/terrain acceptance.

The biome producer uses that same unchanged original export for the full 65
biome definitions and two minimal preset definitions. Its generated JSON slices
retain all climate, effects, carvers/features and spawn fields. This is full
resource data, not the smaller `Biome.NETWORK_CODEC` representation. Definition
syntax bounds are identical to those above; the new producer does not implement
runtime biome codec evaluation or resolve generation/spawn reference behavior.

Expanded multinoise parameters come from the independently frozen actual
`MultiNoiseBiomeSourceParameterList.knownPresets()` census, not from the minimal
JSON preset resources or copied Overworld formulas. The unchanged
[`data/biome-parameters-1.21.8.json`](data/biome-parameters-1.21.8.json) has independent
byte/SHA pins plus retained normal/-O origin receipts. The dedicated build-only
parser caps bytes at 2 MiB, nodes at 262144, depth at eight and strings at 64 bytes;
it permits exactly two presets, 7593/five rows, four row fields, six spans and two
integer endpoints. Wrong indexes, unknown keys, duplicate decoded fields,
out-of-domain/reversed spans, extra elements and floats refuse before emission.
Every original quantized integer and parameter position remains intact. The 7598
static native rows occupy at most 850976 bytes, without a startup allocation.
This static data cost is not a Paper performance comparison.

The [biome reference evidence](tests/reference/biome_parameters/README.md) and
[producer ticket](../../../docs/agent-tasks/REG-BIOME-01_ORIGINAL_BIOME_DATA.md)
separate actual data admission from source-only NETWORK/NBT findings. Verify the
adopted census and its meaningful pin/schema negative guards, including Python -O:

```sh
python3 crates/ferrumc-registry/tests/reference/verify_biome_parameters.py
python3 -O crates/ferrumc-registry/tests/reference/verify_biome_parameters.py
python3 crates/ferrumc-registry/tests/reference/test_verify_biome_parameters.py
python3 -O crates/ferrumc-registry/tests/reference/test_verify_biome_parameters.py
python3 crates/ferrumc-registry/tests/reference/verify_builtin_biomes.py
```

The last verifier checks all 65+2 actual original JAR resources, generated raw
byte equality, exact Decimal contents and manifest receipt indexes, using the
same local original cache or `--original-dir` as Worldgen. No Java census rerun
is needed for unchanged adopted data. Biome selection/RTree history, surfaces,
dynamic client registry order, palette mappings and active natural generation
remain separate consumer work. Existing App/World plains-only behavior is unchanged.

The extracted item-to-block snapshot is a reverse mapping and retains the wall
variant for torch, soul torch and redstone torch. `build.rs` preserves the snapshot
but emits each of those items' standing default as its placement base, resolving
both variants by registry name and failing on unrelated mapping drift. Placement
then selects the contextual wall/floor state; support and full attachment semantics
remain separate. See the pinned [Paper reference](../../../docs/PAPER_REFERENCE.md).

Within the crate map this crate may depend only on `ferrumc-core` (the runtime
currently needs nothing from it). It must never depend on the simulation,
networking, or storage lanes.
