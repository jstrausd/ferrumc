# ferrumc-proto-gen

Build-time code generator for the Minecraft 1.21.8 (protocol 772) packet layer.

This crate is **not** a runtime dependency of `ferrumc-proto` and never ships in
the server binary. It is driven exclusively by `cargo xtask generate`, which
writes deterministic, checked-in Rust into
`crates/ferrumc-proto/src/generated/`. There is no dependency cycle: the
direction is `xtask -> ferrumc-proto-gen -> (writes files into) ferrumc-proto`.

## Commands

- `cargo xtask generate` — regenerate the checked-in protocol code in place.
- `cargo xtask generate --check` — regenerate in memory and fail (non-zero exit
  plus a diff) if the committed files have drifted. CI runs this.

Both commands share a single emit path, so `--check` can never disagree with
what `generate` would write.

## Determinism

Generated output must be byte-identical across machines and runs:

- The pinned spec is the vendored `fixtures/protocol/1_21_8/manifest.toml`;
  generation aborts if its protocol/data versions are not `772` / `4440`.
- Files are emitted into a `BTreeMap` (sorted, no map iteration order leaks).
- Every `.rs` file is normalized through the real `rustfmt` (pinned via
  `rust-toolchain.toml`) — never hand-formatted.
- Output is forced to LF line endings with a single trailing newline, and
  `.gitattributes` marks the generated directory `eol=lf`.
- No timestamps, absolute paths, or usernames are ever written into output.

Every generated file carries the header
`// @generated by ferrumc-proto-gen. Do not edit by hand.` followed by a source
pin line naming the vendored `minecraft-data` commit.

## Opaque bounded trailing bytes

`bounded_remaining_bytes(N)` is an **unprefixed raw tail**, stored as
`ferrumc_codec::BoundedBytes<N>`. N is an ASCII decimal literal from 0 through
2,097,152 inclusive; outer and argument whitespace is allowed. Signs,
expressions, malformed or overflowing numbers, and larger caps are refused.
Zero admits only an empty tail. The ceiling is a local allocation policy,
not a Minecraft metadata limit.

Only a packet's direct final field may use this type. It is forbidden in
structs, optional/array expressions, before another field, and as a second
bounded tail. When a packet uses the new type, another field spelled as
`remaining_bytes` (also nested in optional/array expressions) is refused: it
would consume bytes before the final tail. The complete schema is admitted
before emission or output writes. Schemas without the new type retain their
existing `remaining_bytes` and `prefixed_bytes(N)` admission.

Legacy raw tails inside named structs are not recursively audited here; their
existing admission and consumption behavior remains. A preceding such
composite can therefore consume bytes before the bounded field. The new type
is forbidden in all structs, so a bounded tail itself cannot be hidden there.

The generated constructor accepts an already checked `BoundedBytes<N>` and
the getter returns `&BoundedBytes<N>`. Decoding compares `reader.remaining()`
with N **before reading, copying, or allocating**. An excessive tail returns
`ProtoError::Codec(CodecError::BytesTooLong { length, max: N })` and preserves
the reader at the tail's entry position; earlier fields may be consumed.
The generator uses only the wrapper's `new`/`as_slice`, never its prefixed
`read`/`write`. Encoding writes the slice verbatim, with no length prefix or
terminator.

No metadata, serializer, Slot, NBT, or terminator parsing is implied. Internal
`0xff` bytes and bytes after them remain opaque. A shortened tail within N is
also valid at this layer. Errors in preceding scalar fields keep the existing
codec behavior; no packet-wide decoder or encoder rollback is introduced.
