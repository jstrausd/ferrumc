# REG-BIOME-01 — immutable original builtin biome data

Status: implemented; author checks and independent Root review determine
integration. Sole production owner: `server/crates/ferrumc-registry/**`; this
brief is its new evidence document. No World/App/Net/Storage/Sim changes,
dependencies, active generator/configuration changes or Git/board writes.

## Delivered producer

`biome` now supplies every one of the 65 original Minecraft 1.21.8 biome
resources, both multinoise preset resources, and all 7593 Overworld/five Nether
ordered parameter entries. The prior `PLAINS` string remains compatible.
Full definition JSON includes climate, effects, generation and spawn data;
all 67 definitions retain the exact original export RawValue slices and measured
byte/node/depth statistics. The original export and its manifests are unchanged.

`BiomeResourceId` and `BiomeParametersResourceId` are distinct opaque checked
local identities, with exact canonical/bare name lookup, static definitions and
allocation-free ExactSize/DoubleEnded/Fused iteration. Local name-order slots
have no public numeric/default/serialization/unchecked constructor and are not
wire, persisted or original bootstrap IDs. Span/point/entry fields are private.
The immutable entry API preserves all six quantized spans, offset and resolved
biome identity. Slice position is original parameter ordinal, not a biome ID.
No sorting or deduplication changes parameter order/repetition.

Actual generator ownership: `build.rs` invokes private `build/biome_codegen.rs`,
which reads the pinned original export and the pinned adopted census, emitting
`OUT_DIR/biomes_generated.rs` included by `src/biome.rs`. Generated files are never
hand-edited or committed. The existing bounded JSON visitor is now included once
at the build/test root and imported by both build-only producers; its semantics
and old Worldgen limits are unchanged. Existing item/block/entity/worldgen
generated bytes remain identical to the independently checked GEN-05.4 outputs.

## Original source findings and acceptance boundary

Reviewed actual vanilla base/applied sources and relevant source patches are
pinned in `tests/reference/biome_parameters/source-review.json`. Relevant methods
include BiomeData bootstrap, VanillaRegistries, MultiNoise preset provider and
knownPresets, BiomeParametersDumpReport, Climate.Parameter/ParameterPoint codecs,
ParameterList ordering, Biome.DIRECT/NETWORK codecs, RegistrySynchronization and
RegistryDataLoader's resource/network paths, FriendlyByteBuf/NbtIo tag writers.

Original bootstrap order starts THE_VOID, PLAINS and differs from Prismarine's
alphabetic biome table. No Prismarine numeric index is adopted as original
bootstrap authority. Climate codecs use float spans-2..2, offset0..1 and
`(long)(coordinate*10000.0F)`; the census records actual resulting longs and
retains original ParameterList.values order. Actual method export checked19
server CodeSources plus the freshly compiled helper origin. Historical runner
guards are recorded honestly; they are not upgraded or claimed as a new runtime
export under strengthened environment/class-shadow requirements.

Biome.NETWORK_CODEC carries climate/effects and creates empty generation/spawn
settings; full DIRECT data has those additional fields. Registry synchronization
uses the actual supplied registry element order and NETWORK_CODEC, with matching
known packs allowed to omit NBT. FriendlyByteBuf writes NbtIo.writeAnyTag: type
byte plus payload, no root name; writeUnnamedTag differs. These are source
findings, not executed admission of65 client payloads or dynamic registry IDs.
Current App plains-only registryID0 and Flat palette0 remain unchanged. Later
configuration/palette consumers must explicitly agree on one registry order.

This producer adds no RTree, biome selector/history, End source, surface/carver/
feature behavior, chunk generation, active natural world, Survival or plugins.
Static table cost and allocation-free lookup are not a measured CPU/memory
improvement versus equally complete Paper.
